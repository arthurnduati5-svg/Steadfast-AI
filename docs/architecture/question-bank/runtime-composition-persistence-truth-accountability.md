## Final implementation state

- **Runtime composition**: One canonical repository graph (`questionBankRuntimeComposition.ts`) created per application instance. Repository mode resolved centrally via `questionBankRepositoryMode.ts`. Routes receive dependencies through `composeRuntime()`. No per-request repository graph creation. Production mode cannot silently fall back to in-memory.
- **Package 5 persistence**: Marking-run, result-version, and breakdown-item repositories injected via composition. Create/read paths share repository state. No route-local in-memory repository.
- **Package 6 persistence**: Exam-paper persistence is mandatory via `IExamPaperAssemblyPersistence` interface. Successful mutations come from real service/repository calls. Persistence is atomic. Failed persistence produces no partial graph. Idempotent replay returns original persisted result. Conflicting idempotency fails safely. Domain identity (paperId, variantId, policyId, approvalId, bridgeId) is generated by repository `create()` implementations, not HTTP routes. Read routes query persisted state. School isolation enforced.
- **Package 8**: Marking-invocation dependencies come from composition.
- **Package 22**: Lifecycle-closure services share composed repositories.
- **Package 24**: Readiness-board services use injected repositories. Routes do not generate idempotency keys.
- **Package 26**: In-memory and Prisma composition provide equivalent required repository capabilities.
- **Verified-school**: School-scope middleware remains mounted and enforced.
